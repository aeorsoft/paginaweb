Principio de diseño

Una buena automatización intenta usar APIs antes que simular clics con RPA. El robot que hace clics es el último recurso, no el punto de partida.

Simular clics (RPA puro) Último recurso

  • Frágil: se rompe si cambia la interfaz
  • Lento: opera a velocidad de pantalla
  • Difícil de escalar y de auditar
  • Válido solo para sistemas antiguos sin API

Integrar por API Preferido

  • Estable: contrato definido (JSON, códigos de estado)
  • Rápido: milisegundos por operación
  • Escalable, trazable y versionable
  • Seguro: OAuth2, JWT, mínimo privilegio
